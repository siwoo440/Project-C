# Project C - 36일차 개발일지

## 작업 주제

절차적 탐사 맵의 논리 격자 및 랜덤 맵 생성 기반 구축

## 개발 목표

- `30_Exploration`에서 사용할 절차적 탐사 맵 기반 구축
- 실제 Tilemap 구현 전에 논리적인 셀 구조 정의
- 시작 셀을 기준으로 연결된 랜덤 맵 생성
- 중복 좌표 방지
- 시작 지점과 아래층 계단 위치 지정
- 셀 간 상·하·좌·우 연결 상태 저장
- 임시 디버그 화면을 통해 생성 결과 확인

## 구현 내용

### 1. 탐사 셀 종류 정의

`ExplorationCellType`을 추가하여 탐사 맵의 기본 셀 종류를 구분하도록 구성했다.

현재 셀 종류는 다음과 같다.

- `Normal` : 일반 셀
- `Start` : 탐사 시작 셀
- `Stairs` : 아래층 이동용 계단 예정 셀

향후 조우, 이벤트, 보상 등 추가 탐사 요소를 셀 데이터와 연결할 수 있는 기반으로 사용한다.

### 2. 탐사 논리 셀 데이터 구현

`ExplorationMapCell`을 추가했다.

각 셀은 다음 정보를 가진다.

- 격자 좌표
- 셀 종류
- 위쪽 연결 여부
- 오른쪽 연결 여부
- 아래쪽 연결 여부
- 왼쪽 연결 여부

이를 통해 실제 그래픽 타일이 없어도 탐사 맵의 구조와 이동 가능한 방향을 데이터로 관리할 수 있도록 했다.

### 3. 한 층의 맵 데이터 구조 구현

`ExplorationMapData`를 추가했다.

한 번 생성된 탐사 맵은 다음 데이터를 보관한다.

- 생성 Seed
- 전체 셀 목록
- 좌표별 셀 데이터
- 시작 셀 좌표
- 계단 셀 좌표

좌표를 이용하여 특정 셀을 빠르게 조회할 수 있도록 Dictionary 기반 조회 구조도 함께 구축했다.

### 4. 절차적 맵 생성기 구현

`ExplorationMapGenerator`를 추가했다.

맵 생성은 다음 순서로 동작한다.

1. `(0, 0)` 위치에 시작 셀 생성
2. 이미 생성된 셀 중 하나를 무작위 선택
3. 상·하·좌·우 방향 중 하나를 무작위 선택
4. 해당 위치가 비어 있으면 새로운 셀 생성
5. 목표 셀 수까지 반복
6. 전체 셀의 실제 인접 관계 계산
7. 시작점에서 멀리 떨어진 셀을 계단으로 지정

현재 기본 생성 셀 수는 14개이다.

기존 셀에서 새 셀을 확장하는 방식이므로 생성된 모든 셀이 하나의 연결된 탐사 맵을 구성한다.

### 5. 중복 좌표 방지

생성된 좌표는 `HashSet<Vector2Int>`로 관리한다.

이미 존재하는 위치가 다시 선택되었을 경우 해당 생성을 취소하고 새로운 위치를 다시 선택하도록 구성했다.

이를 통해 하나의 격자 위치에 여러 셀이 중복 생성되는 문제를 방지했다.

### 6. 시작 지점 구현

탐사 맵의 시작 셀은 항상 `(0, 0)`에 생성된다.

해당 셀은 `Start` 타입으로 설정되며 디버그 화면에서는 `S`로 표시된다.

이를 통해 이후 플레이어의 실제 탐사 시작 위치를 논리 맵과 연결할 수 있는 기준점을 마련했다.

### 7. 계단 위치 선정

생성된 셀 중 시작점과 떨어진 위치를 탐색하여 `Stairs` 타입으로 지정한다.

현재는 맨해튼 거리를 기준으로 시작점에서 멀리 떨어진 후보를 선택하며, 동일한 최대 거리의 셀이 여러 개 존재할 경우 무작위로 하나를 결정한다.

계단 셀은 디버그 화면에서 `▼`로 표시된다.

실제 계단 이동과 다음 층 진행은 이후 개발 단계에서 연결한다.

### 8. 셀 연결 관계 계산

맵 생성 완료 후 각 셀의 상·하·좌·우 좌표에 다른 셀이 존재하는지 검사한다.

이를 통해 각 셀이 어느 방향으로 연결되어 있는지 저장한다.

현재 연결 데이터는 디버그 맵의 선을 표시하는 데 사용하며 이후 실제 탐사 이동과 Tilemap 통로 생성에도 사용할 수 있다.

### 9. 30_Exploration 자동 연결

`ExplorationMapRuntimeBootstrap`을 구현하여 `30_Exploration` Scene이 로드될 때 절차 맵 런타임이 자동으로 생성되도록 구성했다.

따라서 Hierarchy에 별도의 GameObject를 수동으로 생성하거나 Inspector에서 Script를 연결하지 않아도 된다.

기존 탐사 플레이어, 조우, 전투 루프와 독립적인 구조로 추가하여 기존 기능에 대한 영향을 최소화했다.

### 10. 맵 런타임 구현

`ExplorationMapRuntime`을 추가했다.

`30_Exploration` 진입 시 다음 동작을 수행한다.

- 임시 Seed 생성
- 14개의 논리 셀 생성
- 시작 셀 지정
- 계단 셀 지정
- 생성 결과 Console 출력
- 디버그 맵 화면 준비

F9 키를 누르면 새로운 Seed를 사용해 맵을 다시 생성할 수 있다.

### 11. 절차 맵 디버그 화면 구현

`ExplorationMapDebugView`를 추가했다.

화면에서 다음 내용을 확인할 수 있다.

- 현재 생성 Seed
- 전체 맵 형태
- 셀 간 연결
- 시작 셀
- 계단 셀
- F9 재생성 안내

표시 기호는 다음과 같다.

- `S` : 시작 지점
- `·` : 일반 셀
- `▼` : 계단 지점

실제 Tilemap을 구현하기 전에 절차 생성 알고리즘이 정상적으로 작동하는지 확인하기 위한 임시 화면이다.

## 현재 단계의 제한 사항

현재 절차 맵은 논리 데이터와 디버그 표시 단계이다.

아직 다음 기능은 연결하지 않는다.

- 실제 플레이어의 셀 단위 이동
- 계단을 통한 다음 층 이동
- 절차 맵 셀에 몬스터 조우 배치
- 전투 후 같은 맵 Seed 및 상태 복원
- 실제 Tilemap 기반 맵 생성

해당 기능은 이후 탐사 시스템 개발 단계에서 순차적으로 연결한다.

## 완료 결과

36일차를 통해 앞으로 사용할 절차적 탐사 맵의 기본 데이터 구조와 랜덤 생성 기반을 구축했다.

탐사 맵은 `(0, 0)`의 시작 셀에서 확장되며, 모든 셀이 서로 연결된 상태를 유지한다. 각 셀은 자신의 격자 좌표와 인접 방향 정보를 가지고 있으며 시작점과 계단 위치도 별도로 관리한다.

`30_Exploration`에서는 별도의 Scene 설정 없이 논리 맵이 자동으로 생성되고, 임시 디버그 화면을 통해 생성 결과를 즉시 확인할 수 있다.

이 구조를 기반으로 다음 단계에서 층 진행, 절차적 조우 배치, 맵 상태 보존, 실제 Tilemap 생성 기능을 순차적으로 연결할 수 있게 되었다.
