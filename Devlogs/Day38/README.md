# Project C - 38일차 개발일지

## 작업 주제

절차적 탐사 조우 배치 시스템 구축

## 개발 목표

- 기존 고정 좌표 기반 탐사 조우 생성 방식 제거
- 절차적으로 생성된 탐사 맵의 일반 셀에 전투 조우 랜덤 배치
- 시작 셀과 계단 셀에는 조우가 생성되지 않도록 제한
- 기존 EncounterData를 전투 조우 템플릿으로 재사용
- 층마다 서로 다른 조우 위치와 전투 데이터 배치
- 조우별 런타임 ID를 통해 동일 EncounterData의 반복 사용 지원
- 계단 이동과 F9 맵 재생성 시 조우도 함께 재생성
- 디버그 맵에서 조우 셀을 확인할 수 있도록 표시

## 구현 내용

### 1. 기존 고정 조우 생성 방식 제거

기존 `ExplorationPrototypeBootstrap`에서는 `EncounterData.ExplorationPosition` 값을 사용하여 조우 오브젝트를 고정된 월드 좌표에 생성했다.

38일차부터 해당 고정 조우 생성 기능을 제거하고 `ExplorationMapRuntime`이 현재 절차 맵을 기준으로 조우를 생성하도록 변경했다.

이에 따라 탐사 플레이어와 HUD 생성은 기존 Bootstrap이 담당하고, 맵·계단·조우 배치는 절차 맵 런타임이 담당하도록 역할을 분리했다.

### 2. 일반 셀 기반 절차 조우 배치

현재 절차 맵에서 `Normal` 타입인 셀만 조우 후보로 사용한다.

다음 셀에는 조우를 생성하지 않는다.

- `Start`
- `Stairs`

현재 한 층에서는 기본적으로 최대 3개의 일반 셀을 선택하여 전투 조우를 배치한다.

이를 통해 시작 위치에서 즉시 전투가 발생하거나 계단과 조우가 겹치는 상황을 방지했다.

### 3. 조우 배치 후보 랜덤 선택

현재 맵의 일반 셀 목록을 수집한 후 현재 맵 Seed를 기반으로 순서를 무작위화한다.

그중 최대 3개의 셀을 선택하여 조우를 배치한다.

따라서 같은 층에서 새 맵을 생성하면 서로 다른 위치에 조우가 생성될 수 있다.

### 4. EncounterData 템플릿 재사용

기존 `Resources/Encounters`의 `EncounterData`를 계속 사용한다.

현재 절차 조우에서는 `EncounterData`의 다음 정보를 전투 데이터로 활용한다.

- 조우 ID
- 표시 이름
- BattleType
- 등장 적
- 캐릭터 경험치 보상
- Gold 보상
- 나사 보상
- 철판 보상
- 전선 보상

기존 `ExplorationPosition`은 절차 조우의 실제 배치 위치로 사용하지 않는다.

유효한 EncounterData가 존재하지 않을 경우 조우를 생성하지 않고 Console에 경고를 출력하도록 구성했다.

### 5. 절차 조우 오브젝트 생성

선택된 일반 셀의 논리 좌표를 `GetWorldPosition()`을 통해 임시 월드 좌표로 변환한다.

해당 위치에 다음 구성의 조우 오브젝트를 런타임 생성한다.

- SpriteRenderer
- CircleCollider2D
- ExplorationEncounterView

조우는 임시 색상 사각형으로 표시하며 플레이어가 Trigger에 접촉하면 기존 전투 Scene 진입 구조를 그대로 사용한다.

### 6. 런타임 조우 ID 도입

동일한 `EncounterData`가 여러 층과 여러 셀에서 반복 사용될 수 있도록 조우 배치 자체를 구분하는 런타임 ID를 추가했다.

현재 런타임 ID는 다음 정보를 기반으로 생성한다.

- 현재 층
- 셀 X 좌표
- 셀 Y 좌표
- 현재 맵 Seed

예시:

```text
F2_X1_Y-3_S123456
```

이를 통해 동일 EncounterData를 사용하더라도 서로 다른 위치의 조우를 개별 전투로 구분할 수 있다.

### 7. ExplorationEncounterView 확장

`ExplorationEncounterView`가 기존 EncounterData뿐 아니라 런타임 조우 ID도 함께 전달받도록 수정했다.

플레이어가 조우에 접촉하면 다음 정보를 `ExplorationSessionManager`에 전달한다.

- 런타임 조우 ID
- EncounterData
- 플레이어 위치
- 조우 위치

기존 `Initialize(EncounterData)` 방식도 호환성을 위해 유지했다.

### 8. 탐사 세션 조우 관리 개선

`ExplorationSessionManager`가 현재 전투의 런타임 조우 ID를 별도로 저장하도록 수정했다.

전투 승리 시 EncounterData의 ID 자체가 아니라 현재 배치의 런타임 조우 ID를 클리어 목록에 기록한다.

이를 통해 같은 EncounterData를 사용하는 다른 절차 조우까지 함께 제거되는 문제를 방지했다.

도주 또는 패배 시에는 해당 런타임 조우를 클리어 처리하지 않는다.

### 9. 층 이동 시 조우 재생성

계단을 통해 다음 층으로 이동하면 다음 흐름으로 동작한다.

1. 현재 층 증가
2. 이전 조우 오브젝트 제거
3. 새로운 Seed 생성
4. 새로운 절차 맵 생성
5. 계단 위치 갱신
6. 새로운 일반 셀 선택
7. 새로운 조우 배치
8. 플레이어를 새 시작 위치로 이동

이를 통해 층마다 새로운 맵과 새로운 전투 조우 구성을 생성할 수 있다.

### 10. F9 맵·조우 재생성

기존 F9 디버그 기능을 확장했다.

F9를 누르면 현재 층은 유지하면서 다음 항목을 새로 생성한다.

- 맵 Seed
- 논리 맵
- 계단 위치
- 조우 위치
- 조우 데이터

재생성 후 플레이어는 현재 맵의 시작 위치로 이동한다.

### 11. 디버그 맵 조우 표시

`ExplorationMapDebugView`를 수정하여 절차 조우 위치를 `E` 기호로 표시한다.

현재 표시 기호는 다음과 같다.

- `S` : 시작 셀
- `E` : 전투 조우 셀
- `·` : 일반 빈 셀
- `▼` : 계단 셀

디버그 패널에는 현재 층의 조우 개수도 함께 표시한다.

### 12. 탐사 HUD 갱신

기존 탐사 안내 UI를 38일차 절차 조우 테스트 기준으로 수정했다.

현재 HUD에서 다음 정보를 확인할 수 있다.

- 현재 탐사 층
- 캐릭터 레벨과 경험치
- 호감도
- 보유 자원
- 이번 탐사에서 클리어한 런타임 조우 수

층이 변경되면 현재 층 정보도 갱신되도록 처리했다.

## 현재 단계의 제한 사항

38일차에서는 절차 조우 생성과 전투 연결까지만 구현한다.

아직 전투 Scene을 거쳐 탐사로 돌아왔을 때 기존 층의 다음 상태를 완전히 복원하지 않는다.

- 현재 맵 Seed
- 현재 셀 구조
- 조우 배치 위치
- 이미 클리어된 현재 맵의 셀 상태

이 상태 보존 기능은 다음 탐사 개발 단계에서 연결한다.

또한 현재 조우는 아직 일반·엘리트·보스 등의 역할을 절차적으로 구분하지 않으며, 실제 Tilemap 탐사 맵도 아직 사용하지 않는다.

## 완료 결과

38일차를 통해 기존 고정 위치 탐사 조우를 절차 맵 기반의 랜덤 조우 배치 구조로 교체했다.

절차 맵의 일반 셀 중 일부가 전투 조우 셀로 선택되고, 기존 EncounterData를 전투 템플릿으로 사용하여 실제 탐사 화면에 조우 오브젝트가 생성된다.

각 조우는 층·셀·Seed를 기반으로 한 런타임 ID를 가지므로 같은 EncounterData를 여러 위치에서 재사용하면서도 개별 조우의 클리어 상태를 구분할 수 있다.

이제 탐사 시스템은 절차 맵 생성, 층 진행, 절차 조우 배치까지 연결되었으며 다음 단계에서 현재 층 Seed와 맵 상태를 보존하는 구조를 추가할 수 있는 기반이 마련되었다.
