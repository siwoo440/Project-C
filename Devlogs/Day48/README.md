# Project C - 48일차 개발일지

## 작업 주제

탐사 방 형태 다양화 및 조우 랜덤 배치 시스템 구축

## 개발 목표

- 기존 7x7 정사각형 방만 생성되던 구조 확장
- 일반 방에 여러 형태의 방 생성 규칙 추가
- 시작 방과 계단 방은 안전한 형태로 제한
- 동일 Seed에서 동일한 방 형태가 재생성되도록 처리
- 기존 상하좌우 통로 연결 유지
- 방 내부의 실제 이동 가능한 Floor 기준으로 조우 위치 선택
- 벽과 출입구 주변을 피한 안전한 조우 배치
- 전투 후 탐사 복귀 시 동일 Seed 기준 방과 조우 위치 재현
- 기존 조우 클리어 및 전투 진입 구조 유지

## 구현 내용

### 1. 방 형태 종류 확장

`ExplorationTilemapView`에 절차 생성용 방 형태를 추가했다.

```text
Square
Horizontal
Vertical
LShape
TShape
Cross
```

기존에는 모든 논리 셀이 동일한 7x7 정사각형 Floor로 변환되었으나, 이제 일반 방은 현재 맵 Seed와 방 좌표를 기준으로 여섯 형태 중 하나를 선택한다.

### 2. 방 형태 회전

L자형과 T자형처럼 방향에 따라 형태가 달라지는 방을 위해 90도 단위 회전 규칙을 추가했다.

```text
0도
90도
180도
270도
```

회전 값 역시 Seed 기반으로 결정되므로 동일한 탐사 Seed에서는 같은 방이 같은 방향으로 재생성된다.

### 3. 시작 방 안전성 유지

시작 방은 플레이어 최초 배치를 안정적으로 유지하기 위해 정사각형으로 고정했다.

```text
Start
→ Square
```

이를 통해 탐사 시작 직후 플레이어가 좁은 형태나 잘린 공간에 배치되는 상황을 방지한다.

### 4. 계단 방 형태 제한

계단이 항상 안정적인 중앙 Floor 위에 존재하도록 계단 방은 복잡한 형태를 제외했다.

```text
Stairs
→ Square
→ Horizontal
→ Vertical
```

계단 방도 Seed에 따라 형태가 선택되지만 L자형, T자형, 십자형은 사용하지 않는다.

### 5. 방 중앙 이동 공간 보장

모든 방은 형태와 관계없이 중앙 3x3 Floor를 확보하도록 처리했다.

이를 통해 다음 위치가 항상 안정적으로 유지된다.

```text
플레이어 시작 위치
계단 기본 위치
방 중심 이동 공간
```

### 6. 연결 방향 Floor 보장

기존 논리 맵의 상하좌우 연결 정보를 유지하면서 다양한 형태의 방에서도 통로가 끊기지 않도록 연결 방향의 Floor를 강제로 확보했다.

```text
논리 방 연결 정보
↓
방 형태 생성
↓
중앙 이동 공간 확보
↓
연결 방향 출입로 확보
↓
기존 Corridor 연결
```

따라서 L자형이나 T자형 방이 선택되어도 연결된 인접 방으로 이동할 수 있는 구조를 유지한다.

### 7. 방별 Floor 데이터 저장

`ExplorationTilemapView`가 전체 Floor만 관리하던 구조에서 각 논리 방별 실제 Floor 셀도 따로 저장하도록 확장했다.

```text
논리 방 좌표
→ 실제 방 Floor 목록
```

이 데이터는 조우 위치뿐 아니라 이후 이벤트, 상점, 보물, 상호작용 오브젝트 등의 방 내부 랜덤 배치에도 재사용할 수 있는 기반이 된다.

### 8. 조우 위치를 방 중심에서 랜덤 위치로 변경

기존 조우는 다음 방식으로 생성되었다.

```text
조우 방 선택
→ 해당 방 중심 좌표
→ 조우 오브젝트 생성
```

48일차부터는 다음 구조를 사용한다.

```text
조우 방 선택
↓
해당 방 실제 Floor 목록 조회
↓
안전한 Spawn 후보 계산
↓
Seed 기반 후보 선택
↓
조우 오브젝트 배치
```

`ExplorationMapRuntime`은 기존 `GetWorldPosition()`을 직접 사용하지 않고 우선 `TryGetRandomEncounterPosition()`을 통해 랜덤 위치를 요청한다.

### 9. 안전한 조우 Spawn 후보 계산

조우가 벽이나 출입구에 지나치게 붙지 않도록 안전 후보를 계산한다.

주요 기준:

```text
실제 방 Floor 위
벽에 바로 붙지 않은 위치
연결된 출입구 주변 제외
방 중앙 바로 주변 제외
```

안전 후보가 존재하면 해당 목록 중 하나를 Seed 기반으로 선택한다.

### 10. 조우 위치 Fallback 처리

복잡하거나 좁은 방에서 안전 조건을 만족하는 위치가 하나도 없을 수 있기 때문에 완화된 후보 목록을 추가로 사용한다.

```text
안전 후보 확인
↓
없음
↓
완화 후보 확인
↓
없음
↓
기존 방 중심 위치 사용
```

따라서 방 형태 때문에 조우 오브젝트 자체가 생성되지 않는 상황을 방지한다.

### 11. 동일 Seed 재현성 유지

방 형태와 조우 위치 모두 다음 값을 기반으로 별도의 결정적 난수 Seed를 만든다.

```text
Map Seed
+
Room Coordinate
+
기능별 Salt
```

HashSet의 순서에 따라 결과가 달라지지 않도록 조우 후보를 정렬한 뒤 난수를 적용한다.

따라서 동일한 탐사 Seed를 다시 생성하면 동일한 방 형태와 조우 위치를 얻도록 구성했다.

### 12. 기존 조우 시스템 유지

48일차에서는 조우 ID, 전투 진입, 클리어 기록, 탐사 복귀 후 제거 구조는 변경하지 않았다.

```text
논리 방 좌표
→ Encounter ID
→ 전투 진입
→ 승리
→ Cleared Encounter 기록
→ 탐사 복귀
→ 해당 조우 제거
```

조우의 논리적 위치는 기존 방 좌표를 그대로 사용하고, 실제 화면에서 서 있는 World 위치만 방 내부 랜덤 위치로 변경했다.

## 현재 단계의 제한 사항

- 방 형태는 런타임 Tilemap 규칙으로 생성되는 프로토타입이며 정식 환경 아트는 아직 적용하지 않았다.
- 현재 방 형태 종류는 여섯 종류로 제한된다.
- 시작 방은 안전성을 위해 Square로 고정된다.
- 계단 방은 Square, Horizontal, Vertical만 사용한다.
- 조우 위치는 현재 방당 하나의 조우 오브젝트를 기준으로 선택한다.
- 장애물, 이벤트, 상점, 보물 등 다른 탐사 오브젝트의 랜덤 배치는 아직 연결하지 않았다.
- GitHub 저장소에는 현재 Unity Editor 컴파일 또는 Play Mode 자동 CI 검사가 등록되어 있지 않으므로 최종 동작 검증은 로컬 Unity 실행 결과를 기준으로 한다.

## 완료 결과

48일차를 통해 탐사 맵은 단순히 방 연결 구조만 달라지는 단계에서 실제 방 내부 형태까지 달라지는 구조로 확장되었다.

```text
절차적 논리 맵 생성
↓
방별 Seed 기반 형태 선택
↓
방 중앙 및 연결 통로 확보
↓
실제 Tilemap 생성
↓
방별 안전 Spawn 위치 계산
↓
적 조우 랜덤 배치
```

동일 Seed에서는 같은 방 형태와 조우 위치를 재현하며, 새로운 Seed에서는 방 형태와 조우 위치가 함께 달라진다.

이 작업으로 이후 탐사 이벤트, 보물, 상점 NPC, 특수 오브젝트 등을 방 내부의 안전한 랜덤 위치에 배치할 수 있는 기초 구조가 마련되었다.
