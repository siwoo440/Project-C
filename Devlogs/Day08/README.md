# 8일차 개발일지 - 카드 셔플·드로우·손패·버린 카드 더미 구축

---
## 개발 목표

7일차에서 생성한 `CardInstance`와 `BattleDeckRuntime`을 기반으로 전투 중 카드가 이동하는 기본 흐름을 구축하는 것을 목표로 진행했다.

원본 `DeckData`와 `CardData`는 그대로 유지하고, 전투용 카드 인스턴스를 뽑을 카드 더미, 손패, 버린 카드 더미로 나누어 관리하도록 확장했다.

8일차 완료 기준은 다음과 같다.

- 전체 카드와 영역별 카드 목록 분리
- 전투 시작 카드 셔플
- 시작 손패 드로우
- 최대 손패 제한
- 손패 카드 버리기
- 빈 카드 더미 재구성
- 카드 총수와 중복 상태 검증
- 카드 상태 확인용 테스트 메뉴 추가

## 카드 이동 구조

전투 중 카드 이동 흐름은 다음과 같다.

1. 전체 카드 인스턴스를 뽑을 카드 더미에 등록
2. 뽑을 카드 더미 셔플
3. 뽑을 카드 더미에서 손패로 카드 이동
4. 손패에서 버린 카드 더미로 카드 이동
5. 뽑을 카드 더미가 비면 버린 카드 더미를 다시 이동
6. 재구성된 뽑을 카드 더미 셔플
7. 중단된 드로우 계속 진행

카드는 항상 뽑을 카드 더미, 손패, 버린 카드 더미 중 한 곳에만 존재한다.

---
## 1. BattleDeckRuntime 영역 분리

기존 전체 카드 목록을 유지하면서 다음 런타임 영역을 추가했다.

- `Cards`: 처음 생성된 전체 카드 인스턴스
- `DrawPile`: 현재 뽑을 수 있는 카드
- `Hand`: 현재 손패에 있는 카드
- `DiscardPile`: 손패에서 버린 카드

각 목록은 외부 시스템에 `IReadOnlyList`로 제공한다.

각 영역의 카드 수를 확인할 수 있도록 다음 조회 속성도 추가했다.

- 전체 카드 수
- 뽑을 카드 수
- 손패 카드 수
- 버린 카드 수
- 최대 손패 수

---
## 2. 카드 셔플 구현

카드 순서를 섞기 위해 Fisher–Yates 셔플 방식을 적용했다.

런타임 덱 생성 시 전체 카드를 뽑을 카드 더미로 이동한 후 첫 셔플을 실행한다.

일반 전투에서는 무작위 시드를 사용하고, 반복 가능한 테스트가 필요한 경우 지정된 고정 시드를 사용할 수 있도록 구성했다.

셔플은 런타임 카드 목록의 순서만 변경하며 원본 `DeckData`의 카드 순서는 변경하지 않는다.

---
## 3. 카드 드로우 구현

요청한 수만큼 카드를 뽑을 수 있는 드로우 기능을 추가했다.

드로우 규칙:

- 0 이하의 요청은 무시
- 남은 손패 공간까지만 드로우
- 카드 더미 맨 위 카드를 손패로 이동
- 실제로 뽑은 카드 수 반환
- 뽑을 카드와 버린 카드가 모두 없으면 드로우 중단

기본 최대 손패는 5장으로 설정했다.

---
## 4. 카드 버리기 구현

손패에 있는 특정 `CardInstance`를 버린 카드 더미로 이동하는 기능을 추가했다.

버리기 규칙:

- 빈 카드 입력 거부
- 손패에 존재하지 않는 카드 거부
- 손패에서 제거된 카드만 버린 카드 더미에 등록
- 성공 여부 반환

8일차에서는 실제 카드 사용 효과 대신 Context Menu 테스트를 통해 손패 첫 카드를 버린다.

---
## 5. 빈 카드 더미 재구성

드로우 중 뽑을 카드 더미가 비면 버린 카드 더미를 확인한다.

버린 카드가 존재하는 경우 다음 과정을 자동 실행한다.

1. 버린 카드를 뽑을 카드 더미로 이동
2. 버린 카드 더미 비우기
3. 뽑을 카드 더미 셔플
4. 카드 드로우 계속 진행

버린 카드도 없는 경우에는 더 이상 뽑을 카드가 없으므로 드로우를 종료한다.

---
## 6. 덱 상태 검증

카드 이동 이후 런타임 덱의 상태를 자동으로 검사하도록 구성했다.

검증 항목:

- 전체 카드 수와 영역별 카드 수 합계 일치
- 동일한 카드 인스턴스의 영역 중복 방지
- 빈 카드 인스턴스 방지
- 모든 전체 카드의 현재 위치 확인
- 최대 손패 수 초과 방지

잘못된 상태가 발견되면 예외를 발생시켜 이후 시스템이 손상된 덱 상태를 계속 사용하지 않도록 했다.

---
## 7. 상태 변경 이벤트

드로우, 버리기, 셔플로 덱 상태가 변경되면 `StateChanged` 이벤트가 발생하도록 추가했다.

현재는 테스트 로그를 통해 상태를 확인하며, 다음 카드 UI 단계에서는 이 이벤트를 이용해 손패 화면을 자동 갱신할 수 있다.

---
## 8. BattleSceneSetup 연결

전투 초기화 과정에 카드 더미 생성과 시작 손패 드로우를 연결했다.

기본 설정:

| 설정 | 값 |
|---|---|
| 최대 손패 | 5장 |
| 시작 손패 | 3장 |
| 고정 셔플 시드 사용 | 사용 안 함 |
| 테스트용 고정 시드 | 12345 |

변경된 초기화 순서:

1. 전투 편성과 씬 설정 검사
2. 아군과 적 전투 유닛 생성
3. 런타임 덱 생성
4. 전체 카드를 뽑을 카드 더미에 등록
5. 카드 더미 셔플
6. 시작 손패 3장 드로우
7. 카드 영역별 수량 출력

카드 관련 설정은 `40_Battle` 씬의 `BattleSceneSetup` 컴포넌트에도 직접 저장했다.

---
## 9. Context Menu 테스트 기능

`BattleSceneSetup`에 다음 테스트 메뉴를 추가했다.

- `테스트/카드 상태 출력`
- `테스트/카드 한 장 드로우`
- `테스트/손패 첫 카드 버리기`
- `테스트/뽑을 카드 더미 섞기`

기존 `테스트/카드 인스턴스 출력` 기능도 유지했다.

카드 상태 출력에는 다음 정보가 포함된다.

- 전체 카드 수
- 뽑을 카드 수
- 손패 카드 수
- 버린 카드 수
- 덱 상태 정상 여부
- 현재 손패 카드 정보

## 10. 테스트 덱 보강

기존 `Deck_Test`에는 카드가 한 장만 등록되어 있어 셔플, 최대 손패, 버린 카드 재구성을 충분히 확인할 수 없었다.

동일한 `Card_TestAttack`과 소유 캐릭터 조합을 5장으로 늘려, 하나의 카드 원본이 서로 다른 카드 인스턴스로 생성되는 구조를 함께 검증할 수 있도록 했다.

## 8일차 결과

전투용 카드 인스턴스를 뽑을 카드 더미, 손패, 버린 카드 더미로 나누고 셔플, 시작 손패, 추가 드로우, 카드 버리기, 빈 카드 더미 재구성 흐름을 구축했다.

카드가 이동할 때마다 전체 카드 수와 영역 중복을 검사하여 카드가 사라지거나 복제되는 상태를 방지했다.

또한 덱 상태 변경 이벤트를 추가하여 다음 단계에서 손패 UI가 카드 이동에 맞춰 자동으로 갱신될 수 있는 기반을 마련했다.
