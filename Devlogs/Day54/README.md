## 1. 개발 목표

54일차의 목표는 Prototype v0.1에서 사용할 수 있는 상점 시스템을 구축하고,
탐사 회차의 실제 자원·카드·유물·포션 상태와 연결하는 것이다.

핵심 목표는 다음과 같다.

- 카드 상품을 구매할 수 있도록 한다.
- 유물 상품을 구매할 수 있도록 한다.
- 일반 포션 상품을 구매할 수 있도록 한다.
- Prototype v0.1 상점에서는 부활 포션을 제외한다.
- 구매 시 실제 플레이어 골드를 차감한다.
- 상품 지급 실패 시 차감한 골드를 환불한다.
- 구매한 카드는 현재 탐사 회차 덱에 추가한다.
- 보유 카드 1장을 골드를 지불해 제거할 수 있도록 한다.
- 상점 상품을 이미지·이름·가격 구조의 카드 UI로 표시한다.
- 상품 카드는 한 줄에 4개씩 서로 겹치지 않도록 배치한다.

## 2. 주요 변경 내용

### 2.1 Prototype v0.1 상점 카탈로그 추가

`ShopCatalog_Test.asset`을 추가하여 54일차 테스트용 상점 상품을 구성했다.

현재 카탈로그는 다음과 같이 구성되어 있다.

| 종류 | 수량 | 임시 가격 |
| --- | ---: | ---: |
| 카드 | 3개 | 80 / 90 / 100 Gold |
| 유물 | 2개 | 220 / 260 Gold |
| 일반 포션 | 2개 | 각 60 Gold |
| 카드 제거 서비스 | 1종 | 150 Gold |

Prototype v0.1 범위에 맞춰 부활 포션은 상점 카탈로그에서 제외했다.

현재 카탈로그는 기능 검증용 고정 테스트 데이터이며,
최종 상점 상품 풀과 밸런스 가격을 의미하지 않는다.

---

### 2.2 상점 거래 서비스 구축

`IShopWallet`, `ShopTransactionService`, `ShopPurchaseResult`를 추가하여
상품 구매와 카드 제거의 공통 거래 규칙을 분리했다.

일반 상품 구매는 다음 순서로 처리한다.

1. 상품 ID와 가격을 검증한다.
2. 이미 구매한 상품인지 확인한다.
3. 상품을 실제로 지급할 수 있는 상태인지 확인한다.
4. 플레이어의 Gold를 차감한다.
5. 카드·유물·포션을 실제 보유 상태에 지급한다.
6. 지급에 실패하면 차감한 Gold를 전액 환불한다.
7. 정상 지급된 상품은 판매 완료 상태로 기록한다.

이를 통해 Gold만 차감되고 상품이 지급되지 않는 상태를 방지할 수 있는
원자적 거래 흐름을 구성했다.

---

### 2.3 실제 플레이어 Gold 연결

`ShopRunManager`를 추가하여 상점 거래를
기존 `PlayerResourceManager`의 실제 Gold와 연결했다.

상점에서는 별도의 임시 화폐를 사용하지 않으며,
구매 및 카드 제거 시 현재 플레이어 Gold가 실제로 차감된다.

Prototype 기능 검증을 위해
`테스트 Gold +500` 버튼도 함께 제공한다.

---

### 2.4 카드·유물·포션 구매 연결

상품 종류에 따라 실제 지급 대상을 분리했다.

| 상품 종류 | 지급 대상 |
| --- | --- |
| 카드 | `RunDeckManager` |
| 유물 | `RelicRunManager` |
| 포션 | `ConsumableRunManager` |

유물은 이미 보유한 유물의 중복 구매를 차단하고,
포션은 소모품 인벤토리에 빈 슬롯이 있는 경우에만 구매할 수 있도록 연결했다.

카드 상품은 현재 회차 덱에 해당 카드 소유자가 포함되어 있을 때만
추가할 수 있도록 구성했다.

---

### 2.5 탐사 회차 덱 관리자 추가

`IDeckCardEntry`, `RunDeckCardEntry`, `RunDeckManager`를 추가했다.

기존 `DeckData`를 직접 수정하지 않고,
탐사 회차 동안 사용할 카드 목록을 별도로 복사하여 관리한다.

회차 덱에서는 다음 기능을 제공한다.

- 원본 덱 기반 회차 카드 목록 초기화
- 상점 구매 카드 추가
- 보유 카드 제거
- 현재 카드 수 조회
- 카드 소유자 포함 여부 조회
- 다음 전투에 사용할 현재 카드 목록 제공

카드 제거 시에는 최소 1장의 카드를 유지하도록 하여
완전히 빈 전투 덱이 만들어지는 것을 방지한다.

---

### 2.6 상점 변경 사항의 다음 전투 반영

`BattleDeckRuntime`과 `BattleSceneSetup`을 수정하여
전투 시작 시 원본 `DeckData`만 사용하는 대신
`RunDeckManager`의 현재 회차 카드 목록을 사용할 수 있도록 확장했다.

따라서 상점에서 구매하거나 제거한 카드가
다음 전투의 실제 드로우 덱에 반영되는 구조가 마련됐다.

기존 `DeckCardEntry`에는 `IDeckCardEntry` 규약을 적용하여
원본 덱 카드와 회차 덱 카드를 동일한 전투 덱 생성 경로에서 처리한다.

---

### 2.7 탐사 Scene 상점 자동 연결

`ShopPrototypeBootstrap`을 추가하고
`ExplorationSceneRuntimeRouter`에서 탐사 런타임 루트에 자동으로 연결하도록 수정했다.

탐사 Scene이 준비되면 다음 순서로 상점을 구성한다.

1. 현재 탐사 파티의 `BattleLoadout`을 조회한다.
2. `Resources/Shop/ShopCatalog_Test` 카탈로그를 불러온다.
3. `ShopRunManager`와 회차 덱을 준비한다.
4. Prototype 상점 Canvas를 생성한다.

상점 화면을 열면 탐사 진행을 정지하고,
닫을 때 기존 `Time.timeScale`을 복원한다.

---

### 2.8 카드형 상점 UI 구성

상점 상품 표시 방식을 세로형 사각 카드 UI로 구성했다.

각 상품 카드는 위에서부터 다음 순서로 표시한다.

1. 상품 이미지
2. 상품 종류
3. 상품 이름
4. 상품 가격

상품 이미지가 없는 항목은 대체 문구를 표시하며,
판매가 완료된 상품에는 판매 완료 상태를 표시한다.

긴 상품명은 카드 영역을 벗어나지 않도록 자동 크기 조절과
말줄임 처리를 적용했다.

---

### 2.9 한 줄 4개 고정 상품 배치

상품 목록은 `GridLayoutGroup`을 사용해
한 줄에 정확히 4개의 상품 카드가 배치되도록 구성했다.

| 항목 | 값 |
| --- | ---: |
| 열 수 | 4 |
| 카드 크기 | 286 × 400 |
| 카드 간격 | 20 × 24 |
| 내부 좌우 여백 | 각 20 |
| 배치 방향 | 왼쪽 위에서 가로 우선 |
| 스크롤 방향 | 세로 |

카드 사이에는 양수 간격을 두어 서로 겹치지 않도록 했으며,
상품 목록 또는 카드 제거 목록으로 전환할 때
스크롤 위치가 맨 위로 복귀하도록 정리했다.

---

### 2.10 카드 제거 서비스

상점 상품 목록에 `보유 카드 1장 제거` 서비스를 추가했다.

서비스를 선택하면 현재 회차에서 보유 중인 카드가
동일한 카드형 UI로 표시되며,
선택한 카드 1장을 150 Gold를 지불하고 제거한다.

카드 제거에 실패하면 Gold를 환불하며,
최소 1장의 카드는 반드시 유지하도록 제한했다.

---

### 2.11 Editor 테스트 추가

`ShopTransactionServiceTests`를 추가하여
상점 핵심 규칙을 검증할 수 있는 테스트를 구성했다.

현재 작성된 테스트 항목은 다음과 같다.

- 상품 그리드가 4열 고정인지 확인
- 4장의 카드가 기준 폭 안에서 겹치지 않는지 확인
- 정상 구매 시 Gold 차감 및 판매 완료 처리 확인
- Gold 부족 시 자원과 상품 상태가 유지되는지 확인
- 인벤토리 공간 부족 시 Gold가 차감되지 않는지 확인
- 상품 지급 실패 시 Gold가 환불되는지 확인
- 카드 제거 성공 시에만 비용이 차감되는지 확인

GitHub 커밋에는 별도의 CI 상태 검사가 등록되어 있지 않으므로,
Unity Test Runner에서의 실제 실행 결과는 로컬 프로젝트에서 확인한다.

## 3. 상점 이용 흐름

54일차 기준 Prototype 상점 흐름은 다음과 같다.

### 상점 진입

탐사 Scene에서 `상점 열기` 버튼을 선택한다.

상점 화면이 열리는 동안 탐사 시간 진행은 정지된다.

### 상품 확인

카드, 유물, 일반 포션과 카드 제거 서비스가
세로형 상품 카드 형태로 표시된다.

상품은 한 줄에 4개씩 배치되고,
상품 수가 많아지면 세로 스크롤로 다음 줄을 확인한다.

### 상품 구매

상품을 선택하면 현재 Gold와 지급 가능 상태를 확인한다.

구매에 성공하면 Gold가 차감되고
상품이 해당 회차 인벤토리 또는 덱에 지급된다.

이미 판매된 상품은 다시 구매할 수 없다.

### 카드 제거

카드 제거 서비스를 선택하면 현재 회차 덱의 카드 목록으로 전환된다.

제거 가능한 카드를 선택하면 150 Gold를 차감하고
해당 카드를 현재 회차 덱에서 제거한다.

### 다음 전투

카드를 구매하거나 제거한 뒤 다음 전투에 진입하면
`BattleSceneSetup`이 `RunDeckManager`의 현재 카드 목록을 사용하여
전투용 런타임 덱을 생성한다.

따라서 상점에서 발생한 덱 변경 사항이 다음 전투에 이어진다.

## 6. 54일차 결과

54일차에서는 Prototype v0.1 상점 시스템의 기본 거래 흐름을 구축했다.

카드, 유물, 일반 포션을 실제 Gold로 구매할 수 있으며,
카드 제거 서비스와 상품 지급 실패 시 환불 처리까지 포함했다.

또한 기존 원본 덱을 직접 변경하지 않는 `RunDeckManager`를 추가하고
전투 시작 시 현재 회차 카드 목록을 사용하도록 연결하여,
상점에서 구매하거나 제거한 카드가 이후 전투에 이어질 수 있는 기반을 마련했다.

상점 UI는 이미지, 상품 이름, 가격을 세로로 표시하는 카드형 구조로 정리했으며
한 줄에 4개의 카드가 서로 겹치지 않도록 고정 그리드로 배치했다.

54일차 기준 상점 기능은 Prototype 기능 검증에 필요한 범위를 충족하며,
최종 상품 랜덤 편성, 최종 가격 밸런스,
새 탐사 회차 시작 시 상점·회차 덱 초기화 시점은
후속 탐사 및 절차 생성 통합 단계에서 확정한다.
