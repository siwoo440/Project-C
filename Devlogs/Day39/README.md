# Project C - 39일차 개발일지

## 작업 주제

탐사 층 Seed 및 현재 상태 보존 시스템 구축

## 개발 목표

- 전투 Scene을 다녀와도 현재 탐사 층의 Seed 유지
- 동일 Seed를 이용한 논리 맵 구조 복원
- 동일 Seed를 이용한 계단 위치 복원
- 동일 Seed를 이용한 절차 조우 위치와 EncounterData 재현
- 승리한 조우만 제거하고 남은 조우 유지
- 전투 후 플레이어의 기존 복귀 위치 유지
- 다음 층 진입 시 새로운 Seed 생성
- F9 사용 시 현재 층을 새로운 Seed로 강제 재생성
- 탐사 전체 초기화 시 현재 층 Seed도 함께 초기화

## 구현 내용

### 1. 현재 층 Seed 세션 저장

`ExplorationSessionManager`에 현재 층의 절차 생성 Seed를 저장하는 상태를 추가했다.

현재 관리하는 값은 다음과 같다.

- 현재 탐사 층
- 현재 층 Seed
- 현재 층 Seed 존재 여부
- 현재 전투 조우
- 현재 런타임 조우 ID
- 전투 후 복귀 위치
- 클리어한 런타임 조우 목록

이를 통해 `30_Exploration` Scene이 다시 로드되더라도 현재 층의 Seed를 유지할 수 있게 했다.

### 2. 현재 층 Seed 조회 기능 추가

현재 층에 이미 Seed가 존재하는지 확인할 수 있도록 `TryGetCurrentFloorSeed()` 기능을 추가했다.

탐사 Scene 진입 시:

- 저장된 Seed가 존재하면 기존 층 복원
- 저장된 Seed가 없으면 새로운 층 생성

방식으로 분기한다.

### 3. 현재 층 Seed 저장 및 초기화 기능 추가

현재 층 Seed를 직접 저장하는 기능과 Seed 상태를 초기화하는 기능을 추가했다.

새로운 층을 생성할 때는 새로운 Seed를 저장하고, 다음 층으로 이동할 때는 이전 Seed를 제거하여 다음 층에서 새로운 Seed가 생성되도록 했다.

### 4. 전투 복귀 위치 초기화 기능 분리

F9로 현재 층을 강제 재생성할 때 이전 맵의 전투 복귀 위치가 남지 않도록 `ClearReturnPosition()` 기능을 추가했다.

F9 재생성 후 플레이어는 새 맵의 시작 위치로 이동한다.

### 5. 현재 층 복원 또는 신규 생성 분리

`ExplorationMapRuntime`의 기존 무조건 신규 생성 방식을 변경했다.

탐사 Scene이 시작되면 다음 순서로 처리한다.

1. 현재 층 Seed 존재 여부 확인
2. Seed가 있으면 동일 Seed 사용
3. Seed가 없으면 신규 Seed 생성
4. 지정 Seed로 논리 맵 생성
5. 계단 배치
6. 절차 조우 배치

이를 통해 전투 Scene에서 탐사 Scene으로 돌아왔을 때 새로운 맵이 생성되는 문제를 방지했다.

### 6. 지정 Seed 기반 층 구축

현재 층 생성 처리를 `BuildCurrentFloor()` 구조로 분리했다.

해당 기능은 전달받은 Seed를 사용하여 다음 요소를 다시 구성한다.

- 14셀 논리 맵
- 시작 셀
- 계단 셀
- 셀 연결 정보
- 절차 조우 위치
- 조우에 사용되는 EncounterData

같은 Seed를 사용하면 같은 논리 구조가 다시 생성된다.

### 7. 신규 층과 복원 층 상태 구분

현재 생성된 층이 신규 생성인지 세션에서 복원된 것인지 확인할 수 있도록 상태값을 추가했다.

디버그 맵에서는 다음처럼 표시된다.

```text
39일차 상태 보존 | 1F | 신규
```

전투 후 같은 층으로 돌아오면:

```text
39일차 상태 보존 | 1F | 복원
```

으로 표시된다.

### 8. 조우 데이터 순서 고정

동일 Seed를 사용하더라도 `Resources.LoadAll<EncounterData>()`의 반환 순서가 달라질 가능성에 대비해 유효한 EncounterData를 `EncounterId` 기준으로 정렬하도록 수정했다.

따라서 같은 Seed에서는 다음 항목이 안정적으로 재현된다.

- 조우 셀 위치
- 각 조우에서 선택되는 EncounterData

### 9. 클리어 조우 상태 유지

38일차에서 도입한 런타임 조우 ID 구조를 그대로 활용한다.

런타임 조우 ID는 다음 요소를 기반으로 구성된다.

- 현재 층
- 셀 X 좌표
- 셀 Y 좌표
- 현재 Seed

전투 승리 후 탐사로 돌아오면 같은 Seed로 동일한 런타임 ID가 다시 계산된다.

이미 클리어 목록에 존재하는 ID의 조우는 다시 생성하지 않으므로 승리한 조우만 제거되고 나머지 조우는 동일한 위치에 유지된다.

### 10. 전투 후 플레이어 복귀 위치 유지

전투 진입 전에 저장된 복귀 위치는 탐사 Scene 전환 중에도 유지된다.

전투 후 탐사로 돌아왔을 때 저장된 복귀 위치가 존재하면 플레이어를 새 시작 셀로 이동시키지 않고 기존 위치를 우선 사용한다.

따라서 전투 후 같은 탐사 위치에서 자연스럽게 진행을 이어갈 수 있다.

### 11. 다음 층 진입 시 새 Seed 생성

계단을 사용하면 현재 층을 증가시키고 이전 층 Seed를 초기화한다.

이후 다음 층 생성 과정에서 새로운 Seed를 만들어 저장한다.

예:

```text
1F / Seed A
↓ 계단
2F / Seed B
```

따라서 전투 복귀와 새로운 층 진입을 구분할 수 있다.

### 12. F9 강제 재생성 개선

F9는 현재 층을 유지하면서 새로운 Seed로 맵을 다시 생성하는 개발용 기능으로 유지했다.

F9 실행 시:

1. 새로운 Seed 생성
2. 현재 층 Seed 교체
3. 기존 전투 복귀 위치 제거
4. 새로운 논리 맵 생성
5. 계단 재배치
6. 조우 재배치
7. 플레이어를 새 시작 위치로 이동

순서로 처리한다.

이후 전투를 진행하면 F9로 변경된 Seed 기준의 맵이 복원된다.

### 13. 탐사 전체 초기화 보완

`ResetExploration()` 실행 시 기존 탐사 상태와 함께 현재 층 Seed도 초기화하도록 수정했다.

초기화되는 주요 상태는 다음과 같다.

- 클리어 조우 목록
- 현재 조우
- 런타임 조우 ID
- 전투 복귀 위치
- 마지막 클리어 보상
- 현재 층
- 현재 층 Seed

### 14. 디버그 UI 갱신

`ExplorationMapDebugView`를 39일차 테스트 기준으로 수정했다.

현재 표시 정보:

- 현재 층
- 신규 / 복원 상태
- 현재 Seed
- 시작 셀 `S`
- 조우 셀 `E`
- 계단 셀 `▼`
- 현재 남은 조우 개수
- F9 재생성 안내

### 15. 탐사 HUD 안내 수정

기존 절차 조우 테스트 문구를 39일차 상태 보존 테스트 기준으로 변경했다.

HUD에서 전투 후 동일 Seed·맵·조우 배치가 복원된다는 점과 승리한 조우만 제거된다는 점을 확인할 수 있도록 안내를 수정했다.

## 현재 단계의 제한 사항

39일차에서 구현한 상태 보존은 게임 실행 중 Scene 전환을 위한 세션 단위 보존이다.

아직 게임을 종료한 뒤 다시 실행했을 때 상태를 복원하는 영구 저장 시스템은 구현하지 않는다.

또한 현재 탐사 맵은 아직 논리 격자와 임시 월드 오브젝트를 사용하며 실제 Tilemap 기반 탐사 지형은 이후 단계에서 구현한다.

## 완료 결과

39일차를 통해 전투 Scene을 오가더라도 현재 탐사 층이 새로 생성되지 않고 기존 Seed를 기반으로 동일한 맵 상태를 복원할 수 있게 되었다.

같은 Seed를 이용해 맵 구조, 계단 위치, 조우 배치와 EncounterData를 재현하며 런타임 조우 ID와 클리어 목록을 이용해 승리한 조우만 제거한다.

또한 새로운 층에서는 새로운 Seed가 생성되고 F9를 사용할 경우 현재 층을 새로운 Seed로 강제 재생성할 수 있도록 구분했다.

이를 통해 36~39일차에 구축한 절차 맵 생성, 층 진행, 절차 조우, 상태 보존이 하나의 탐사 세션 구조로 연결되었다.
