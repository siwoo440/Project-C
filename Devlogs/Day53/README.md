## 1. 개발 목표

53일차의 목표는 52일차에서 유지하도록 정리한 사망 상태를
거점 회복 시스템으로 연결하는 것이다.

핵심 목표는 다음과 같다.

- 탐사에서 사망한 아군을 즉시 부활시키지 않는다.
- 탐사 종료 후 사망 캐릭터를 회복 상태로 등록한다.
- 회복은 이후 탐사 완료 횟수에 따라 진행한다.
- 회복 중인 캐릭터는 출전 불가 상태로 판정할 수 있도록 한다.
- 회복이 끝나면 저장 HP를 정상적인 생존 상태로 되돌린다.
- 기존 HP·정신력 영속 구조를 그대로 유지한다.

---

## 2. 주요 변경 내용

### 2.1 캐릭터 회복 관리자 추가

`CharacterRecoveryManager`를 새로 추가했다.

회복 관리자는 런타임에서 자동으로 생성되며
`DontDestroyOnLoad`를 사용해 Scene 전환 중에도 회복 상태를 유지한다.

주요 역할은 다음과 같다.

- 탐사 종료 상태 감시
- 기존 회복 캐릭터의 남은 탐사 횟수 감소
- 이번 탐사에서 새로 사망한 캐릭터의 회복 등록
- 회복 완료 캐릭터의 저장 HP 복구
- 사망·회복 중 캐릭터의 출전 가능 여부 조회
- UI에서 사용할 수 있는 남은 회복 횟수 조회

---

### 2.2 탐사 종료 기반 회복 진행

회복 진행은 `ExplorationSessionManager.IsExplorationCompleted`를 기준으로 처리한다.

한 번의 탐사가 종료되면 다음 순서로 동작한다.

1. 기존에 회복 중이던 캐릭터의 남은 탐사 횟수를 1 감소시킨다.
2. 남은 횟수가 0이 된 캐릭터는 회복 완료 처리를 시도한다.
3. 그 후 이번 탐사에서 새로 사망한 캐릭터를 회복 상태로 등록한다.

신규 사망자를 기존 회복 진행 이후에 등록하도록 하여
사망한 탐사 자체가 회복 1회로 즉시 계산되지 않도록 구성했다.

---

### 2.3 Prototype v0.1 임시 회복 규칙

53일차에서는 회복 흐름을 검증하기 위해
Prototype v0.1 임시 수치를 사용한다.

| 항목 | 임시 값 |
| --- | --- |
| 회복 필요 탐사 횟수 | 2회 |
| 회복 완료 HP | 최대 HP의 100% |
| 정신력 | 기존 저장값 유지 |

회복 횟수와 회복 완료 HP는 최종 밸런스 값이 아니며
추후 데이터화 또는 기획 확정 단계에서 조정한다.

---

### 2.4 회복 완료 전용 HP 복구 기능 추가

`BattleResultManager`에 `RestoreRecoveredAlly()`를 추가했다.

이 기능은 회복 설비 처리가 끝난 캐릭터의 저장 HP를
다시 생존 가능한 값으로 변경하는 전용 경로다.

주요 처리 내용은 다음과 같다.

- 유효한 캐릭터인지 확인
- 기존 저장 상태가 준비되어 있는지 확인
- 이미 살아 있는 캐릭터의 중복 복구 차단
- 지정된 회복 HP 비율을 1~100% 범위로 제한
- 최소 HP 1 이상으로 생존 상태 복구
- 정신력 저장값은 변경하지 않음
- 상태 변경 후 파티 UI 갱신 이벤트 호출

52일차에서 제거한 전투·탐사 중 즉시 부활 기능은 다시 추가하지 않았다.

---

### 2.5 사망·회복 상태 조회와 출전 판정 기반 구축

`CharacterRecoveryManager`에 다음 조회 기능을 추가했다.

- `IsDead()`
- `IsRecovering()`
- `GetRemainingRecoveryExpeditions()`
- `TryGetRecoveryState()`
- `CanDeploy()`
- `CanDeployParty()`

이를 통해 후속 파티 편성 UI와 출전 시스템에서
사망 또는 회복 중인 캐릭터를 선택 불가 상태로 처리할 수 있는 기반을 마련했다.

현재 53일차에서는 출전 가능 여부를 판정하는 시스템 API까지 구축하며,
실제 파티 편성 UI의 버튼 비활성화와 회색 표시 등은 후속 UI 연결 단계에서 처리한다.

## 3. 회복 흐름

53일차 기준 전체 흐름은 다음과 같다.

### 캐릭터 사망

탐사 또는 전투에서 HP가 0이 되면
52일차의 상태 영속 구조에 따라 사망 상태가 유지된다.

### 탐사 종료

탐사가 성공 또는 실패로 종료되면
회복 관리자가 현재 출전 파티의 저장 HP를 확인한다.

HP가 0인 신규 사망 캐릭터는 회복 상태로 등록된다.

### 이후 탐사 진행

이미 회복 중이던 캐릭터는
다른 파티의 탐사가 한 번 종료될 때마다 남은 회복 횟수가 감소한다.

Prototype v0.1에서는 2회의 후속 탐사가 필요하다.

### 회복 완료

남은 횟수가 0이 되면
`BattleResultManager.RestoreRecoveredAlly()`를 통해 저장 HP를 복구한다.

회복 상태가 제거되며
다시 출전 가능한 캐릭터로 판정된다.

## 5. 확인 항목

- Unity 프로젝트에서 컴파일 오류가 없는지 확인
- 사망 캐릭터가 전투 종료 후 HP 0 상태를 유지하는지 확인
- 탐사 종료 후 사망 캐릭터가 회복 상태로 등록되는지 확인
- 신규 사망 캐릭터의 회복 횟수가 즉시 감소하지 않는지 확인
- 다음 탐사 종료 후 남은 횟수가 2회에서 1회로 감소하는지 확인
- 그다음 탐사 종료 후 회복이 완료되는지 확인
- 회복 완료 시 HP가 Prototype v0.1 기준 최대 HP로 복구되는지 확인
- 회복 과정에서 정신력이 임의로 초기화되지 않는지 확인
- `CanDeploy()`가 사망 또는 회복 중 캐릭터에 대해 `false`를 반환하는지 확인
- 회복 완료 캐릭터가 다시 출전 가능 상태로 판정되는지 확인
- 같은 탐사 종료가 여러 프레임에서 중복 처리되지 않는지 확인
- 기존 즉시 부활 기능이 다시 생기지 않았는지 확인

## 6. 53일차 결과

53일차에서는 52일차에서 유지하도록 정리한 사망 상태를
이후 탐사 진행과 연결되는 회복 시스템으로 확장했다.

사망 캐릭터는 탐사 종료 후 회복 상태로 등록되고,
이후 탐사 완료 횟수에 따라 회복이 진행된다.

회복 완료 시에만 저장 HP를 되돌리는 전용 경로를 추가해
전투 중 즉시 부활과 거점 회복을 분리했다.

또한 사망 여부, 회복 여부, 남은 회복 횟수,
캐릭터와 파티의 출전 가능 여부를 조회할 수 있는 API를 추가하여
후속 파티 편성 UI와 거점 회복 시설 화면에서 사용할 수 있는 기반을 구축했다.
