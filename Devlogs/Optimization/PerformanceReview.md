# Windows 전투·탐사·저장 최적화

전투 손패는 남아 있는 카드와 입력 영역을 다시 사용한다. 휴식 창은 실제 덱 슬롯이 바뀐 행만 다시 만들고, 강화 수치가 바뀐 행의 문구를 갱신한다. 탐사 적은 같은 두 셀과 같은 바닥 구성의 시야 판정을 재사용한다. 새 층을 만들면 시야 판정과 지역 조우 후보를 다시 조회한다. 자동 저장은 교체 직전 기존 원본을 한 번 읽으며 최신 버전 보호와 이전 정상본 복구를 유지한다. 카드 행동의 대상 선택과 손패 비용 선택은 같은 클래스의 별도 파일로 분리했다.

## Windows 에셋

| 배포 설정의 비교 항목 | 적용 전 | 적용 후 |
| --- | ---: | ---: |
| `Gallery_Data` 파일 합계 | 1,073,730,487 B | 916,398,375 B |
| Unity 보고서의 텍스처 | 958.6 MiB | 808.5 MiB |
| 대표 상태 아이콘 1종 | 6.0 MiB | 1.0 MiB |

전투와 도감이 공유하는 상태 이미지 30종의 Windows 임포트 상한을 1024로 조정했다. 원본 PNG와 에셋 식별자는 유지했다. `Gallery_Data`는 약 157.3 MB 줄었다. 도감에서 원화와 설명 표시를 1600×900 및 1280×800 두 해상도로 확인했다. 한 번의 배포 설정 실행에서 첫 프로젝트 폰트 초기화는 22.03 ms, 첫 1024×1024 글리프 아틀라스는 1,048,576 B였다.

## 반복 플레이 실측

같은 Windows PC의 Unity 6000.3.21f1 Development Player와 Direct3D 11을 사용했다. 시드 91701, 동일한 네 캐릭터와 덱으로 거점, 윈터폴 탐사, 자동 추격, 유리 재 들판 사건, 카드 사용과 적 턴, 도주와 같은 층 복귀, 상점, 휴식 강화와 자동 저장을 실행했다. 두 해상도에서 변경 전후 각 3회, 총 12회에서 프레임 50,514개와 메서드 호출 59,738개를 수집했다. 두 빌드의 예열 실행은 비교 표본에서 제외했다.

| 항목 | 1600×900 적용 전 → 후 | 1280×800 적용 전 → 후 |
| --- | ---: | ---: |
| 전체 플레이 프레임 중앙값 | 0.774 → 0.741 ms | 0.769 → 0.761 ms |
| 전체 플레이 프레임 95백분위 | 1.907 → 1.887 ms | 2.095 → 2.214 ms |
| 전투 손패 갱신 중앙값 | 0.854 → 0.686 ms | 0.858 → 0.712 ms |
| 전투 구간 프레임당 최대 관리 할당 | 860,514 → 387,830 B | 860,700 → 387,632 B |
| 휴식 강화 뒤 목록 갱신 95백분위 | 4.311 → 0.012 ms | 4.707 → 0.012 ms |
| 추격 물리 갱신 95백분위 | 0.0047 → 0.0050 ms | 0.0046 → 0.0045 ms |
| 자동 저장 파일 쓰기 95백분위 | 35.884 → 27.846 ms | 30.878 → 27.935 ms |
| 거점에서 탐사까지 중앙값 | 733.9 → 786.1 ms | 765.9 → 749.7 ms |
| 탐사에서 전투까지 중앙값 | 1274.9 → 1270.0 ms | 1267.7 → 1274.5 ms |
| 전투 뒤 탐사 복귀 중앙값 | 219.6 → 221.2 ms | 220.7 → 218.4 ms |

전체 프레임의 관리 할당량 95백분위는 두 해상도 모두 8,376 B였다. 1600×900에서 같은 층 복귀 시 Unity가 추적한 메모리 중앙값은 152,653,030 B에서 152,634,376 B로 바뀌었다. 회차마다 복귀를 한 번 측정했다. 1280×800 전체 프레임 지연과 두 해상도의 추격 구간 프레임 지연은 증가했다. 개선 빌드의 첫 예열에서는 저장 파일 쓰기 4.802초가 한 차례 발생했다. 원인 확인과 장시간 반복 측정은 299일차에 포함했다.

[프레임과 할당량](frame-summary.csv) · [메서드](method-summary.csv) · [장면 전환](transition-summary.csv) · [메모리](memory-samples.csv)

별도 Windows 실행본에서 같은 시드의 탐사 시작 구역에 추격 개체 4개를 배치했다. 모두 플레이어를 추격해 실제 위치가 바뀌었다. 1280×800, 60 FPS 제한, 수직 동기화 해제 조건에서 개체 배치 전후로 각각 프레임 48개를 수집했다. 프레임 간격 95백분위는 16.6734 ms에서 16.6695 ms였다. 이 실행은 제한 설정에서 네 개체가 동시에 움직이는지 확인하기 위한 것이다.

## 리소스 참조와 호환성

상점과 전투의 시제품 에셋은 런타임 장면과 저장 카탈로그에서 쓰인다. 구형 윈터폴 저장은 기존 조우 식별자로 복원된다. 참조가 있는 에셋을 유지하고 큰 텍스처의 Windows 임포트 설정부터 줄였다. 291일차 배포 점검에 개발용 입력과 테스트 포션 지급 분리를 배정했다.
