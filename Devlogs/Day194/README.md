# 194일차 UI·조작과 탐사 성능 점검

같은 플레이 세션에서 로비와 탐사 사이를 세 번 왕복했다. **탐사 진입은 287.7~500.2ms, 로비 복귀는 272.0~288.2ms**였다. 세 번 모두 유물 창에서 이동이 멈췄고, 창을 닫으면 같은 D 키 입력으로 이동을 재개했다. 마지막 복귀 후에도 로비 탐사 버튼으로 지역 선택 화면을 열었다.

점검 중 첫 귀환 후 로비 탐사 버튼에 활성 캔버스가 연결되지 않아 다시 출발할 수 없는 문제를 발견했다. 로비 컨트롤러가 로비 씬에 지정된 캔버스에 메뉴를 만들도록 수정했다. 캔버스가 미지정된 로비도 자기 씬의 활성 루트 캔버스만 검색한다.

---
## 측정 결과

2026-11-19 Windows Unity Editor `6000.3.21f1`, Direct3D 12, 게임 화면 640×480에서 측정했다. 이 실행에서 왕복 검사를 포함한 관련 테스트 9개가 모두 통과했다. 표의 메모리는 Unity 전체 할당량이고, 1MiB는 1,048,576바이트다.

| 회차 | 측정 시점 | 전환 시간(ms) | 할당량(바이트) | 첫 로비 대비(MiB) |
| --- | --- | ---: | ---: | ---: |
| 기준 | 첫 출발 전 로비 | — | 310,613,196 | 0.00 |
| 1 | 탐사 진입 | 500.2 | 600,921,272 | +276.86 |
| 1 | 로비 복귀 | 272.0 | 605,171,936 | +280.91 |
| 2 | 탐사 진입 | 287.7 | 604,063,221 | +279.86 |
| 2 | 로비 복귀 | 288.2 | 605,202,484 | +280.94 |
| 3 | 탐사 진입 | 303.8 | 604,268,762 | +280.05 |
| 3 | 로비 복귀 | 281.8 | 605,303,601 | +281.04 |

첫 왕복 뒤 로비 메모리는 최초 로비보다 280.91MiB 높았다. 첫 복귀와 세 번째 복귀 사이에는 131,665바이트(약 0.13MiB) 증가했다. 장시간 운용 시의 증가 추세와 다른 장치에서의 전환 시간은 추가 측정이 필요하다.

## 측정 방법

- 첫 로비 화면이 준비된 직후의 메모리를 기준값으로 삼는다. 편성 화면에서 **탐사 출발**을 누르기 직전부터 로딩 화면이 제거되고 탐사 씬의 유물 버튼이 그려져 클릭 대상이 될 때까지 시간을 잰다. 복귀는 정산 화면의 **거점으로 복귀** 버튼을 누르기 직전부터 로비 탐사 버튼이 그려질 때까지 측정한다.
- 탐사에서는 유물 버튼과 확인 버튼의 중앙 좌표를 검사한다. 각 좌표의 최상단 클릭 대상에 입력을 전달하고 창의 표시 상태를 확인한다. 시험용 키보드의 D 키를 게임 입력 버퍼에 눌린 상태로 기록한다. 창이 열린 동안 두 번의 물리 갱신 후에도 제자리여야 하며, 같은 키가 눌린 상태에서 창을 닫으면 실제 플레이어가 오른쪽으로 이동해야 한다.
- 반복 구간을 일정하게 맞추기 위해 각 탐사에서 성공 정산을 코드로 호출한다. 정산 후에는 화면의 복귀 버튼으로 로비에 돌아와 지역 선택 창을 다시 연다.
- 메모리는 Unity Profiler의 `GetTotalAllocatedMemoryLong()` 값이다. 측정 중 가비지 수집이나 미사용 리소스 정리를 강제로 실행하지 않는다. 첫 탐사는 해당 세션의 첫 진입이며 이후 두 번은 재진입이다.

별도 Windows 촬영용 플레이어(Direct3D 11)의 종료 로그에 `GarbageCollector disposing of ComputeBuffer` 경고가 1회 기록됐다. 프로젝트의 `Assets` 아래 C# 소스에서 `ComputeBuffer`를 직접 사용하는 곳은 발견되지 않았다. 버퍼를 생성한 코드와 플레이 중 누수 여부는 확인이 필요하다.

## 재현

Unity `6000.3.21f1`에서 프로젝트 복제본의 Player Settings를 열고 Company Name과 Product Name을 모두 `ProjectCVerification`으로 지정한다. 로비 자동 저장과 안내 설정은 이 프로필을 사용한다. 두 설정이 일치하지 않으면 검사 시작 전에 건너뛴다.

EditMode Test Runner에서 `ExplorationRoundTripTests.ThreeRoundTripsRestoreInputAndReportMemory`를 실행한다. 검사 도중 Play 모드로 진입한다. Editor 로그에서 `[Day194]`를 검색하면 첫 로비의 기준값 1줄과 씬 전환 6줄의 밀리초·바이트 원시 측정값을 확인할 수 있다.
